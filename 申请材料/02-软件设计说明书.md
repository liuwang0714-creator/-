# 瞻途电商交易系统软件 V1.0
## 软件设计说明书

---

## 第 1 章 引言

### 1.1 编写目的

本说明书用于阐述「瞻途电商交易系统软件 V1.0」的系统架构、功能设计、数据库设计与关键技术实现，作为软件著作权登记的鉴别材料，同时供软件开发、测试与维护人员参考。

### 1.2 项目背景

随着电子商务的普及，中小型商家对低成本、可自主管理的在线交易系统的需求日益增长。传统电商系统普遍存在角色权限划分不清晰、商家与用户沟通链路长、订单流转状态混乱、缺乏移动端入口等问题。本软件旨在提供一套覆盖「管理员—商家—用户」三角色协同的电商交易解决方案，以「瞻途」为品牌名，以「前瞻未来 · 途享好物」为品牌口号，打通商品发布、下单、支付、发货、评价、即时沟通的完整闭环，并支持 Web 管理后台与微信小程序移动端双端运行。

### 1.3 术语与缩略语

| 术语 | 含义 |
| --- | --- |
| Sa-Token | 轻量级 Java 权限认证框架，用于登录认证与权限校验 |
| WebSocket | 全双工通信协议，用于实时消息推送 |
| MVC | Model-View-Controller 三层架构模式 |
| ORM | 对象关系映射，本项目使用 MyBatis |
| IM | Instant Messaging，即时通讯 |
| openid | 微信用户唯一标识 |
| ZHAN TU | 瞻途，本软件的品牌名称 |

## 第 2 章 系统概述

### 2.1 系统目标

构建一套支持多角色协同的电子商务交易系统，实现：

1. 三角色（管理员 / 商家 / 普通用户）权限隔离与协同操作；
2. 商品发布、下单、支付、发货、评价的完整交易闭环；
3. 基于 WebSocket 的实时即时通讯；
4. Web 管理后台 + 微信小程序移动端双端覆盖；
5. 平台运营数据可视化统计。

### 2.2 用户角色

| 角色 | 角色编码 | 主要职责 |
| --- | --- | --- |
| 管理员 | admin | 平台运营管理，包括用户管理、商品审核、订单监控、数据统计 |
| 商家 | merchant | 商品发布与维护、订单处理与发货、回复用户咨询 |
| 普通用户 | user | 浏览商品、下单购买、在线支付、收货评价、即时咨询 |

### 2.3 功能概述

系统按业务域划分为八大功能模块：用户与权限管理、商品管理、订单管理、在线支付、收货地址管理、评论互动、即时通讯、后台管理。各模块详细设计见第 4 章。

## 第 3 章 系统架构

### 3.1 总体架构

系统采用前后端分离架构，分为四层：

```
┌─────────────────────────────────────────────────────┐
│                    客户端层                          │
│  ┌──────────────┐  ┌──────────────┐                │
│  │ Web 管理后台  │  │ 微信小程序端  │                │
│  │ (Vue3+Vite)  │  │ (uni-app)    │                │
│  └──────┬───────┘  └──────┬───────┘                │
└─────────┼─────────────────┼────────────────────────┘
          │ HTTP/REST       │ HTTP/REST + WebSocket
┌─────────▼─────────────────▼────────────────────────┐
│                    接入层                           │
│   CORS 跨域处理 · Sa-Token 鉴权拦截器 · 异常处理    │
└─────────┬──────────────────────────────────────────┘
          │
┌─────────▼──────────────────────────────────────────┐
│                  业务逻辑层 (Service)               │
│  用户服务 · 商品服务 · 订单服务 · 支付服务          │
│  地址服务 · 评论服务 · 消息服务 · 文件服务          │
└─────────┬──────────────────────────────────────────┘
          │
┌─────────▼──────────────────────────────────────────┐
│                  数据访问层 (Mapper)                │
│            MyBatis · XML 映射 · 事务管理            │
└────┬─────────────┬─────────────────────────────────┘
     │             │
┌────▼─────┐  ┌────▼─────┐
│ MySQL 8.0│  │ Redis 7  │
│ 业务数据  │  │ 会话缓存  │
└──────────┘  └──────────┘
```

### 3.3 分层架构说明

后端采用标准 MVC 三层架构：

- **Controller 控制层**：接收 HTTP 请求，参数校验，调用 Service，封装统一返回结果 `Result<T>`；
- **Service 业务层**：承载核心业务逻辑，组织事务，调用 Mapper；
- **Mapper 数据访问层**：基于 MyBatis 注解与 XML 映射，执行数据库操作；
- **Pojo 实体层**：与数据库表对应的实体类、数据传输对象（DTO）、统一结果封装。

配套组件包括：`GlobalExceptionHandler` 全局异常处理、`SaTokenConfig` 鉴权拦截器、`CorsConfig` 跨域配置、`WebSocketConfig` WebSocket 端点注册。

## 第 4 章 功能模块设计

### 4.0 品牌门户首页模块

#### 4.0.1 功能描述

Web 端首页作为「瞻途」品牌的门户入口，承担品牌展示、商品导流、平台介绍等核心功能，包含以下子模块：

- **顶部信息栏**：显示欢迎语、快捷链接（我的订单、购物车、会员中心等）；
- **主导航栏**：包含瞻途品牌 Logo、Logo + 品牌名称组合、分类导航、搜索框、快捷操作按钮（购物车、登录/注册）；
- **Hero 视觉区**：大尺寸品牌展示区，包含品牌标语「前瞻未来 · 途享好物」、热门商品推荐、动态视觉效果；
- **商品分类导航**：12 个商品分类入口（数码、服饰、美食、家居、美妆、母婴、运动、图书、汽车、宠物、户外、礼品），每个分类带专属图标与悬停动效；
- **限时秒杀区**：倒计时组件 + 5 个秒杀商品卡片，展示原价、折扣、已售进度；
- **平台数据统计**：6 项核心指标展示（注册用户数、入驻商家数、商品总数、累计订单量、服务城市数、好评率）；
- **瞻途精选商品**：支持「热销榜」「新品上架」「品牌特卖」「百亿补贴」标签切换，每个商品卡片展示图片、名称、价格、销量、评分；
- **六大平台优势**：正品保障、极速物流、7 天无忧、专属客服、会员特权、安全支付；
- **购物流程图解**：浏览→下单→支付→发货→收货→评价 6 步流程可视化；
- **品质保障承诺**：正品保证、急速发货、7 天退换、运费险、专属客服、品质承诺；
- **用户好评展示**：3 条精选评价，包含用户头像、评分、评价内容；
- **瞻途动态资讯**：3 条最新平台公告/行业资讯；
- **商家入驻 Banner**：商家入驻引导，展示商家数据（入驻商家数、服务用户数、日均订单量、 GMV 总额）；
- **合作伙伴区**：8 个合作伙伴 Logo 展示位；
- **APP 下载引导**：移动端 App 下载二维码；
- **页脚信息**：品牌信息、快捷链接、客户服务、关于我们、版权声明、备案信息。

#### 4.0.2 技术实现

- 首页采用单文件组件 `home.vue` 实现，代码量约 2400 行；
- 品牌信息通过 `brand.js` 配置文件集中管理，品牌 Logo 通过 `BrandLogo.vue` 组件复用；
- 响应式设计支持 1200px/992px/768px/480px 四档断点适配；
- 动画效果：CSS 浮动动画、过渡效果、Hover 状态变化；
- 倒计时组件：基于 `setInterval` 实现秒级更新。

### 4.1 用户与权限管理模块

#### 4.1.1 功能描述

- 账号注册：支持注册为商家或普通用户，密码采用 MD5 加密存储；
- 账号密码登录：校验用户名密码及账号状态（正常 / 封禁 / 注销 / 未激活），登录成功后签发 Sa-Token；
- 微信小程序登录：通过 OpenFeign 调用微信 `code2session` 接口换取 openid，已存在则直接登录，不存在则自动注册并授予普通用户角色；
- 用户信息维护：修改昵称、手机号、生日、头像；
- 修改密码：校验原密码后更新，并强制下线；
- 角色判定：提供当前登录用户角色查询接口；
- 用户状态管理：管理员可封禁用户，封禁期间禁止登录。

#### 4.1.2 权限设计

系统定义三种角色：`admin`、`merchant`、`user`，角色与用户为多对多关系（表 `sys_user_role`），并在 `user` 表中冗余 `role_id` 字段简化查询。权限校验通过 `SaTokenConfig` 注册的 `SaInterceptor` 拦截器实现，路由级权限规则如下：

| 路由模式 | 允许角色 | 说明 |
| --- | --- | --- |
| `/user/login`、`/user/register`、`/user/wxlogin`、`/images/**` | 公开 | 登录注册与静态资源放行 |
| `/**`（其余） | 已登录 | 统一校验登录态 |
| `/admin/**` | admin | 管理后台接口 |
| `/goods/**`（写操作） | merchant、admin | 商品管理 |
| `/order/user/**` | user、admin | 用户侧订单 |
| `/order/merchant/**` | merchant、admin | 商家侧订单 |

### 4.2 商品管理模块

- 商品发布：商家录入商品名称、价格、库存、描述、主图；
- 商品列表：分页查询，支持按商品名搜索；
- 商品详情：展示商品信息及主图；
- 库存管理：下单扣减库存，取消订单回滚库存；
- 商品维护：商家修改自有商品信息，管理员可管理全部商品。

### 4.3 订单管理模块

- 下单：用户选择商品、收货地址、购买数量生成订单，系统通过 `OrderIdUtil` 生成全局唯一订单号；
- 订单状态：`0 待支付`、`1 已支付`、`2 已取消`，发货状态 `fahuo` 字段标识 `0 未发货 / 1 已发货`；
- 发货：商家填写快递单号完成发货；
- 订单查询：用户查询自身订单，商家查询店铺订单，管理员查询全平台订单；
- 订单快照：订单表冗余收货人姓名、电话、详细地址，避免地址变更影响历史订单。

### 4.4 在线支付模块

- 支付方式：微信支付（`pay_type=1`）、支付宝支付（`pay_type=2`）；
- 支付状态：`0 待支付`、`1 已支付`、`2 支付失败`、`3 已退款`；
- 支付记录：`pay` 表与 `order` 表通过 `order_id` 唯一关联，记录第三方交易号、支付金额、支付时间；
- 支付回调：第三方支付完成后回调更新订单与支付状态。

### 4.5 收货地址管理模块

- 地址增删改查：用户维护多个收货地址（姓名、手机号、详细地址）；
- 下单选择：下单时关联地址 ID，并将地址快照写入订单表。

### 4.6 评论互动模块

- 一级评论：用户对商品发表评论，支持配图；
- 二级评论（回复）：对一级评论进行回复，表 `comment_to` 通过 `one_id` 关联；
- 点赞：`like_comment` 表合并记录一级 / 二级评论点赞，通过 `uk_comment_user` 唯一索引防重复点赞；
- 评论列表：按商品聚合，展示评论树及点赞数。

### 4.7 即时通讯模块

- 通信协议：基于 Spring WebSocket，端点由 `WebSocketConfig` 注册，`ChatWebSocketHandler` 处理消息；
- 会话管理：`WebSocketSessionManager` 维护用户 ID 与会话映射，支持单发与广播；
- 消息类型：`TEXT` 文本、`IMAGE` 图片；
- 聊天类型：`PUBLIC` 公开、`PRIVATE` 私聊；
- 在线用户：连接建立后广播在线用户列表（`ONLINE` 消息）；
- 权限校验：通过 `ChatPermissionService` / `usersvice.canChatWith` 判定发送者与接收者是否允许通信；
- 消息持久化：所有消息写入 `im_message` 表，支持历史消息查询。

### 4.8 后台管理模块

- 用户管理：用户列表、封禁 / 解封、角色分配；
- 商品管理：全平台商品审核与下架；
- 订单管理：全平台订单监控；
- 数据统计：基于 ECharts 可视化展示销售数据、订单趋势。

| id | int | 主键，自增 |

#### 5.2.2 sys_role（角色表）与 sys_user_role（关联表）

- 触发器 `sync_sur_to_user_insert/update`：角色变更时自动同步 `user.role_id`，简化查询。

| stock | int | 库存 |
| description | varchar(500) | 描述 |

#### 5.2.4 order（订单表）

| 字段 | 类型 | 说明 |

#### 5.2.5 pay（支付记录表）

#### 5.2.6 comment / comment_to / like_comment（评论体系）

- comment：一级评论，含 `user_id`、`goods_id`、`file_id`（配图）、`like_count`、`to_coment_num`（回复数）；
- comment_to：二级回复，含 `one_id` 关联一级评论；
- like_comment：点赞记录，`(comment_id, user_id)` 唯一索引防重。

#### 5.2.7 im_message（即时通讯消息表）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 消息 ID |
| from_user_id | bigint | 发送者 ID |
| to_user_id | bigint | 接收者 ID（NULL 表示群聊） |
| content | text | 消息内容 |
| msg_type | varchar(16) | TEXT / IMAGE |
| chat_type | varchar(16) | PUBLIC / PRIVATE |
| send_time | datetime | 发送时间 |

索引：`idx_from_user`、`idx_to_user`、`idx_send_time`、`idx_chat_type`。

#### 5.2.8 file（文件表）

统一管理商品图、用户头像、评论图，字段含 `file_name`、`file_url`、`file_size`、`create_id`，各业务表通过外键引用 `file.id`。

```
order ──1:1── pay (order_id)
address ──< order (addr_id)
```

## 第 7 章 关键技术实现

### 7.1 基于 Sa-Token 的认证授权

- 登录：`StpUtil.login(userId)` 签发 Token，Token 风格为 UUID，有效期 30 天，存储于 Redis；
- 鉴权：`SaInterceptor` 拦截器配合 `SaRouter` 实现路由级登录校验与角色校验；
- 角色权限：`StpInterfaceImpl` 实现 `StpInterface`，从数据库加载用户角色与权限列表；
- 多端登录：`is-concurrent=true` 允许多端同时在线，`is-share=false` 每次登录生成新 Token；
- 封禁：`StpUtil.isDisable(userId)` 校验账号是否被封禁。

### 7.2 基于 WebSocket 的即时通讯

- 端点注册：`WebSocketConfig` 注册 `/ws/chat` 端点，绑定 `ChatWebSocketHandler`；
- 连接管理：`WebSocketSessionManager` 以用户 ID 为 Key 维护会话映射，提供 `addSession`、`removeSession`、`sendToUser`、`broadcast` 方法；
- 消息处理：`ChatWebSocketHandler` 区分 `CONNECT`（建立会话）与 `MESSAGE`（发送消息），消息持久化后双发至发送者与接收者；
- 在线广播：连接建立 / 断开后，向所有在线用户推送最新在线列表；
- 通讯权限：通过 `usersvice.canChatWith` 限定用户仅可与商家或管理员通讯。

### 7.3 全局唯一订单号生成

`OrderIdUtil` 基于雪花算法思想生成 19 位全局唯一订单号，保证高并发下订单号不重复，订单号同时作为支付记录关联键。

### 7.4 统一异常处理与结果封装

- `GlobalExceptionHandler` 捕获全局异常，统一转换为 `Result` 返回，避免敏感堆栈泄露；
- `Result<T>` 统一封装成功 / 失败 / 特殊状态，前端按 `code` 字段分流处理。

### 7.5 文件上传与静态资源

- 文件上传至服务器本地目录，文件元信息写入 `file` 表，返回访问 URL；
- `LocalImageConfig` 配置静态资源映射，`/images/**` 路径放行鉴权；
- 上传单文件限制 10MB（`spring.servlet.multipart`）。

### 7.6 跨域处理

`CorsConfig` 配置全局 CORS，允许前端开发域名跨域访问后端接口。

## 第 8 章 安全设计

1. 密码安全：用户密码采用 Sa-Token 提供 `SaSecureUtil.md5` 加密存储，不明文落库；
2. 鉴权安全：除登录注册与静态资源外，所有接口强制登录校验，敏感接口按角色二次校验；
3. 越权防护：商品、订单接口校验数据归属，商家仅能操作自有商品与订单；
4. 防重复点赞：`like_comment` 表唯一索引防止用户对同一评论重复点赞；
5. 敏感信息脱敏：提交与对外材料中，数据库密码、微信密钥等均以占位符呈现（详见 [05-代码修改说明.md](./05-代码修改说明.md)）；
6. 异常隔离：全局异常处理器屏蔽内部错误细节，仅返回友好提示。
